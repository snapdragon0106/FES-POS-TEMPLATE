# 障害対応手順書（当日用）

出来上がりは `docs/FES-POS障害対応手順書.pdf`（A4・15ページ）。印刷して配るもの。
システムが止まっているときはWebで読めないので、**PDFで持っておく**のが前提。

- `index.html` — 本体（印刷用CSS込み。説明書 `docs/manual/` と同じデザイン）
- `images/` — 障害を実際に起こして撮った画面（赤い帯・通信断・二重防止・DB停止）

## 構成

1. レジ係の行動カード（全員）— 画面に何が出たら何をするか、紙への切り替え
2. 何が壊れているかの見分け方 — 1台か全台か → `/api/health` の結果で分岐
3. 種類別の直し方 — 端末／会場ネットワーク／Render／TiDB／管理者ログイン／データ
4. 紙での営業と、復旧後の入力
5. 事前の準備チェックリスト（前日まで・当日朝・閉店後）
6. 当日は修正を反映しない
7. 付録 — 紙の売上記録用紙（1ページ・そのまま印刷）、緊急連絡先

## この手順書が前提にしている仕組み

手順書の内容は、次の仕組みがあることを前提にしている。変えたら手順書も直すこと
（詳しくは CLAUDE.md の「当日の障害に備えた設計」）。

- 接続状態の赤い帯（`ConnectionBanner.tsx`）と、その文言
- 「通信が途切れました」→ 同じボタンをもう一度押せば二重にならない（`clientRequestId`）
- 15秒のタイムアウト
- `GET /api/health` の出力形式（`status` / `db` / `commit`）
- DBが戻ればサーバー再起動なしで自動復帰する（mysql2 のコネクションプールが再接続する）

いずれも実際に障害を起こして確認済み（端末の圏外・サーバー停止・応答消失・サーバーの停止状態・DB停止）。
