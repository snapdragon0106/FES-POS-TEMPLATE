1しくみ

FES POS は、3つの無料サービスを組み合わせて動いています。それぞれにアカウントを作って、つなげていきます。

みんなのスマホは、ブラウザ（Safari や Chrome）で Render のアドレス（例：https://fes-pos-abcd.onrender.com）を開いて使います。 アプリをインストールする必要はありません。

無料プランについて（2026年時点）

サービス無料でできること気をつけること
GitHubプログラムを置いておける（自分だけが見られる「Private」でよい）特になし
Renderアプリを1つ動かせる（月750時間・通信は月5GBまで）。このシステムなら2日間の文化祭で数百MB程度15分だれも使わないと休止し、次に開いたとき動き出すまで約1分かかる
TiDB Cloudデータベースを作れる（保存は5GiB・処理は月5000万RUまで）。このシステムの使用量は、その数%程度特になし
文化祭当日の注意 Render は使われていないと休止するので、開店の5〜10分前に、だれか1人がアプリを開いておいてください。 営業中はみんなのスマホが自動で通信し続けるので、休止しません。

このシステムでできること

  • レジ — 商品をタップして会計。お釣りの計算、注文番号の発行
  • 受け渡し — 会計した注文が、商品を渡す係のスマホに数秒で表示される
  • 在庫 — 全員のスマホで残りの数が同じになる。2日目の分を先に登録しておける
  • 現金の管理 — 釣り銭の登録、売上の回収、締め（数えた現金との差額）
  • 売上の集計 — 売上・利益・商品別の数。CSVでダウンロード、学校提出用の報告書をPDFで出力
  • 練習 — 本番と同じ画面で練習して、あとで練習の記録だけをまとめて消せる

2はじめる前に決めること

5章で入力する4つのことを、先に決めておきます。12章の記入シートに書いておくと楽です（ひみつのものは書かないでください）。

① 名簿（番号と名前）

レジを使う人全員の番号と名前です。番号は、ログインのときに入力する数字で、4けたがおすすめです （例：2年3組1番 → 2301）。名前は画面の表示や記録に使います。

書き方は、「番号:名前」を「,」（カンマ）でつなげるだけです。

2301:見本 一郎,2302:見本 花子,2303:見本 次郎,2304:見本 桜
  • 「:」「,」は全角（：、，）でも大丈夫です。名前の中のスペースはそのまま使えます
  • 同じ番号を2回書かないでください
40人分を手で打つのが大変なとき（Excel・Googleスプレッドシート） A列に番号、B列に名前を入れて、C1に =A1&":"&B1 と入れて下までコピーします。 空いているセルに =TEXTJOIN(",",TRUE,C1:C40) と入れると、1行につながった名簿ができます。それをコピーして使います。

② 管理者の番号

管理者は、商品の登録・PINの承認・売上の管理などができる人です。名簿にある番号の中から 1人か2人 決めます。 2人なら 2301,2302 のように書きます。

③ 合言葉

アプリを開くと最初に聞かれる言葉です。クラスの人だけに教えます。外の人が入ってこられないようにするためのものなので、 推測されにくいものにしてください（クラス名や「password」などは避ける。例：sakura-2027 のように、言葉と数字を組み合わせる）。

④ 店の名前

ログイン画面に表示される名前です（例：経高祭 2年3組）。合言葉を入れた人にだけ見えます。

ここまでのまとめ 名簿（2301:見本 一郎,…）・管理者の番号（2301）・合言葉・店の名前、の4つが決まったら次へ進みます。

3GitHub：プログラムを自分用にコピー

先輩が用意した「テンプレート」から、あなた専用のコピー（リポジトリ）を作ります。中身は自動でコピーされるので、ファイルを触る必要はありません。

  1. GitHub のアカウントを作る
    https://github.com を開き、Sign up からメールアドレスで登録します（無料）。すでに持っていればログインします。
  2. テンプレートを見られるようにしてもらう
    テンプレートが「Private（非公開）」の場合は、持ち主（先輩や先生）にGitHubのユーザー名を伝えて、招待してもらいます。 届いたメールの View invitation → Accept invitation を押します。公開されている場合は、この手順はいりません。
  3. テンプレートのページを開く
    持ち主から教えてもらったアドレスを開きます（例：https://github.com/snapdragon0106/fes-pos-template）。
  4. 自分用のコピーを作る
    緑色の Use this template → Create a new repository を押します。
  5. 名前と公開範囲を決める
    Owner：自分のアカウント ／ Repository name：好きな名前（例：fes-pos-2027）／ 公開範囲は Private を選び、Create repository を押します。
できあがり https://github.com/あなたのユーザー名/fes-pos-2027 のようなページができ、ファイルがたくさん並んでいれば成功です。 このページは5章で使います。
「Use this template」のボタンが無いとき テンプレートとして設定されていないか、見る権限がありません。持ち主に「Template repository として設定されているか」「自分が招待されているか」を確認してもらってください（10章の「テンプレートの持ち主へ」）。

4TiDB Cloud：データの保管場所を作る

売上や在庫を保存するデータベースを作り、その「接続先」（住所とパスワードをまとめた1行の文字）を作ります。

  1. アカウントを作る
    https://tidbcloud.com を開き、Sign Up から登録します。Googleアカウントでも登録できます。 最初にいくつか質問が出たら、適当に答えて進めてかまいません。
  2. クラスタ（データベースの入れ物）を作る
    Create Cluster を押し、次のように選んで Create を押します。30秒ほどでできあがります。
    • プラン：Starter（無料。最初から選ばれています）
    • 場所（Region）：Tokyo (ap-northeast-1)（日本に近いほど速い）
    • 名前：何でもよい（例：fes-pos）
  3. 接続の画面を開く
    できたクラスタの名前を押し、右上の Connect を押します。
    Connection Type は Public、Connect With は General のままにします。
  4. パスワードを作る
    Generate Password（パスワードを作る）を押します。パスワードはこのときしか表示されないので、 すぐにメモ帳などにコピーしておきます（忘れたら Reset Password で作り直せます）。
  5. 3つの値をメモする
    画面に出ている HOST（gateway01.ap-northeast-1.prod.aws.tidbcloud.com のような長い文字）、 USERNAME（xxxxxxxx.root のような文字）、PASSWORD の3つをメモします。PORT はふつう 4000 です。

接続先を組み立てる

メモした値を、次の形に当てはめて1行にします。これが「接続先」（DATABASE_URL）です。

mysql://USERNAME:PASSWORD@HOST:4000/fespos

例（実際の値は人によって違います）：

mysql://3xYzAbcDeF.root:aB3dE6gH9jK2mN5p@gateway01.ap-northeast-1.prod.aws.tidbcloud.com:4000/fespos
  • 最後の fespos は、データベースの名前です。まだ無くても大丈夫です（アプリが最初に起動したとき自動で作ります）
  • :（コロン）と @（アットマーク）の位置をまちがえないようにしてください。パスワードに @ : / ? # % などの記号が入っていると読めないので、Reset Password で作り直してください
  • 暗号化の設定は、アプリが自動で付けます。TiDB Cloud の別の画面に出ている ?ssl=… 付きの文字を使ってもかまいません
  • 接続先にはパスワードが入っているので、人に見せないでください。5章で Render に貼り付けたら、メモは消してかまいません

5Render：アプリを動かす

3章のリポジトリを Render につなげて、アプリを動かします。設定はリポジトリに入っている設計図（render.yaml）が自動で読み込むので、入力するのは5か所だけです。

  1. アカウントを作る
    https://render.com を開き、Get Started → GitHub を選んで、GitHub のアカウントで登録します。 「Render に GitHub へのアクセスを許可しますか」と聞かれたら許可します。
  2. Blueprint（設計図）から作る
    Render の画面の右上の New ＋ → Blueprint を押します。
  3. リポジトリを選ぶ
    3章で作ったリポジトリ（例：fes-pos-2027）の Connect を押します。
    一覧に出てこないときは、Configure account（または Connect GitHub）から、Render がそのリポジトリを見られるように許可します。
  4. 名前を付ける
    Blueprint Name に好きな名前（例：fes-pos）を入れます。Branch は main のままです。
  5. 5つの値を入れる
    画面に入力欄が出るので、2章と4章で用意したものを入れます。
入力欄の名前入れるもの例
DATABASE_URL4章で組み立てた接続先mysql://…:4000/fespos
POS_MEMBERS名簿（番号:名前 をカンマでつなげたもの）2301:見本 一郎,2302:見本 花子
POS_ADMIN_IDS管理者の番号2301
POS_ACCESS_CODE合言葉sakura-2027
POS_SHOP_NAME店の名前経高祭 2年3組

JWT_SECRET と POS_ADMIN_RECOVERY_CODE は、Render が自動で作るので入力しなくてかまいません（入力欄が出ない場合もあります）。

  1. 作る
    いちばん下の Deploy Blueprint（または Apply）を押します。プランが Free になっていることを確認してください。
  2. 待つ（5〜10分）
    左の一覧の fes-pos を押すと、作業の様子（ログ）が流れます。Live（緑）になれば完成です。
  3. アドレスを確かめる
    サービスの画面の上のほうに出ている https://fes-pos-xxxx.onrender.com が、アプリのアドレスです。 これをクラスのみんなに伝えます（合言葉とは別に伝えるのがおすすめ）。
「Deploy failed」（失敗）になったとき ほとんどは入力した値のまちがいです。サービスの画面の Logs を開くと、日本語で直す場所が書いてあります （例：「POS_MEMBERS の「…」が読めません」）。左の Environment で値を直して Save Changes を押すと、もう一度作り直されます。 くわしくは11章。

6管理者のはじめてのログイン

新しいお店には、まだ誰のPIN（4けたの暗証番号）もありません。管理者だけは、Render が作った「復旧コード」を使って最初のPINを決めます。

1アドレスを開いて合言葉を入れる

スマホかパソコンで、5章のアドレスを開きます。合言葉を入れて 入場する を押します。

開くまで1分ほどかかることがあります（休止からの起動）。

最初に出る合言葉の画面

2自分の番号を入れる

管理者の番号を入れて 次へ を押します。

上に店の名前が出ていれば、設定が正しく読み込まれています。

店の名前（例：経高祭 2年3組）が表示される

3「管理者の復旧コードを使う」を押す

PINを決める画面が出ますが、ここではPINを入れずに、下の青い文字 管理者の復旧コードを使う を押します。

ここでPINを設定すると「承認待ち」になり、承認できる人がいないので使えません（そうなっても、復旧コードを使えばやり直せます）。

いちばん下の「管理者の復旧コードを使う」

4復旧コードとPINを入れる

復旧コードは Render にあります。Render のサービスの画面の左にある Environment を開き、 POS_ADMIN_RECOVERY_CODE の値（目のマークで表示）をコピーします。

それを「復旧コード」に貼り付け、新しいPIN（4けた）を2回入れて PINを設定する を押します。

1234・0000・1111・生まれ年のような推測されやすいPINは使えません。

復旧コードと新しいPIN

5レジの画面が出たら成功（次の6を忘れずに）

右上に自分の番号と「管理者」が出ていれば成功です。次からは、番号とPINだけで入れます。

まだ商品が無いので、レジには案内だけが出ています。商品は8章で登録します。

管理者でログインしたところ
6. 復旧コードを消す（必ずやる） PINが決まったら、すぐに復旧コードを消してください。残しておくと、コードを知った人（画面写真やLINEで見た人など）が 管理者のPINを勝手に変えて、管理者になりすませます。
Render の Environment で POS_ADMIN_RECOVERY_CODE の右のごみ箱マークを押し、Save Changes を押します （アプリが1〜2分で再起動します）。ログイン画面に「管理者の復旧コードを使う」が出なくなれば消えています。
コードは人に送ったり、写真に撮ったりしないでください。あとで管理者がPINを忘れたときは、同じ名前で16文字以上のでたらめな英数字を 新しく追加すれば、もう一度この手順が使えます（使い終わったら、また消します）。

7メンバーに入ってもらう

クラスのみんなは、自分でPINを決めて申請し、管理者が承認すると使えるようになります。成り済ましを防ぐため、承認は本人の画面に出るコードで行います。

1メンバー：PINを決めて申請する

アドレスを開き、合言葉 → 自分の番号を入れます。はじめてのときは「初回ログイン」と出るので、 自分で決めたPINを2回入れて PINを設定する を押します。

メンバーのはじめてのログイン

2メンバー：申請コードを管理者に見せる

4文字の申請コードが出ます。この画面を管理者に見せます（写真やチャットで送るより、直接見せるのが確実です）。

4文字の申請コード

3管理者：PINタブで承認する

管理者は下の PIN タブを開きます。「承認待ち」に本人の番号と名前が出ているので、本人の画面のコードを入れて 承認 を押します。

そのあとメンバーは、番号とPINで入れるようになります。

コードが合わない申請は承認できません。覚えのない申請は 却下 してください。

承認待ちにコードを入れて承認
人数が多いとき ホームルームなどで、全員に同時にアドレスを開いてもらい、順番に管理者が承認すると早く終わります。 PINを忘れた人は、管理者が PIN タブでリセットできます。
ホーム画面に追加すると便利 iPhone は Safari の共有ボタン → ホーム画面に追加、Android は Chrome の右上 ︙ → ホーム画面に追加。 アプリのように1タップで開けます。

8お店の準備

管理者が、商品・在庫・係などを準備します。どれも、あとから何度でも直せます。

1商品を登録する（商品タブ → 追加）

  • 販売価格：お客さんが払う値段。お釣りが楽になるので、100円単位がおすすめ
  • 原価：1個あたりの仕入れ値（仕入れた金額 ÷ 個数）。利益の計算だけに使います
  • 初期在庫：1日目に売る数
  • 日付を指定して追加する在庫：2日目の分など。日付と個数を入れると、その日の0時に自動で在庫に加わります（1日目の売れ残りも持ち越されます）
  • 警告閾値：残りがこの数以下になると「残りわずか」と出ます
  • 画像：写真を選ぶと、絵文字の代わりに表示されます
商品の追加。2日目の分を日付指定で入れているところ

2在庫を確かめる（在庫タブ）

「残」が今日売れる数、青い札（例：10/4から +78）がその日に加わる数です。
手元にある実物の数 ＝「残」＋ 青い札の数 なので、仕入れた数と合っているか確かめます。

日付を指定した在庫は、その日になる前なら × で取り消せます。今日の日付で登録すると、すぐに売れる在庫になるので注意してください。

在庫タブ

3報告書の設定（会計タブ）

学校に出す収支報告書（仕入帳・売上帳・物品販売報告書）の行事名・団体名・仕入代金の借入金を入れて 保存 を押します。 報告書の日付は自動で入ります。

仕入れたものは「仕入帳」に、保菌検査代などは「控除費目」に記録しておくと、最後に PDF出力 でまとめて印刷できます。

会計タブの設定欄

4練習する（商品タブの「練習」）

練習用の商品を追加 を押すと、¥100 の練習用の商品が3つ入ります。みんなで会計・受け渡し・取消などを練習します。

終わったら 練習を片付ける を押すと、練習の会計がまとめて消え、売上や在庫は練習の前に戻ります。 本番の前に必ず片付けてください。

商品タブのいちばん上の「練習」

そのほかの準備

  • 復旧コードを消した（6章の6）
  • 会計係を決める（PINタブの「会計係」）— 釣り銭の登録・締めができる人
  • 操作説明書と障害対応手順書を印刷して配る（docs のPDF。障害対応手順書の最後にアドレスを書く）
  • 本番の前日までに通し練習（スマホ2台以上で同時に会計・受け渡し・取消を試す）
  • 当日の朝：開店の5〜10分前にアプリを開く → 売上タブで釣り銭を登録 → 営業開始

9文化祭が終わったら

  1. 締め（売上タブ・管理者か会計係）
    レジの現金を金種ごとに数えて入力します。合わなくても無理に合わせず、そのまま記録します。
  2. 釣り銭を返す（最終日だけ）
    用意した釣り銭を返したら、釣り銭を返す で記録します。2日目も同じお金を使うなら、返さずに次の日の朝また釣り銭を登録します。
  3. データを保存する
    売上タブの 取引明細 と 商品別集計 でCSV（Excelで開ける）をダウンロードします。 会計タブの PDF出力 で、学校提出用の報告書を保存・印刷します。
  4. そのあと
    アプリはそのまま置いておいても、無料の範囲なので費用はかかりません。使わなくなったら、Render のサービスの Settings → いちばん下の Delete Web Service で止められます（データは TiDB Cloud に残ります）。

10次の年・ほかのクラスで使うとき

2つの方法があります。おすすめは A です。

A. 新しく作る（おすすめ）

次の年のクラスが、自分たちのアカウントでこの手順書の2章からやり直します。テンプレートから新しいリポジトリを作るので、 前の年のデータや設定は一切入りません。前の年の人のアカウントにも頼りません。

B. 同じ Render と TiDB Cloud を使い続ける

先生など同じ人がアカウントを管理し続ける場合の方法です。Render の Environment で次を変えて Save Changes を押すだけです。

変えるものどう変えるか
DATABASE_URL最後の名前だけ変える（例：/fespos → /fespos2027）。新しい空のデータベースで始まります。去年のデータは前の名前のまま残ります
POS_MEMBERS ／ POS_ADMIN_IDS新しいクラスの名簿と管理者
POS_ACCESS_CODE新しい合言葉（去年の人が入れないように、必ず変える）
POS_SHOP_NAME新しい店の名前
POS_ADMIN_RECOVERY_CODE16文字以上のでたらめな英数字を追加。新しい管理者が6章の手順で最初のPINを決めます
データベースの名前は必ず変える 名前を変えずに名簿だけ変えると、去年の売上や、同じ番号の先輩のPINが残ったままになります。

テンプレートの持ち主へ（先輩・先生向け）

後輩が3章の「Use this template」を使えるように、GitHub のテンプレートのページで次を確認してください。

  • Settings → General の Template repository にチェックが入っている
  • 後輩を招待する：Settings → Collaborators → Add people → 後輩のGitHubユーザー名
  • 卒業する前に、持ち主を先生やクラブのアカウントに移す：Settings → いちばん下の Transfer ownership （移さないと、持ち主がいなくなったときに誰も招待できなくなります）
  • 公開してもよい場合は Settings → Change visibility → Public。プログラムに名簿や合言葉は入っていないので、 公開しても秘密がもれることはありません（招待の手間がなくなります）

11困ったとき

Render が「Deploy failed」になる

サービスの画面の Logs を開き、赤い文字や Error の行を探します。次のようなメッセージが出ていたら、 Environment でその値を直して Save Changes を押します。

ログに出る言葉原因と直し方
POS_MEMBERS の「…」が読めません名簿の書き方。「番号:名前」をカンマでつないでいるか確認
POS_ADMIN_IDS の … が POS_MEMBERS にありません管理者の番号が名簿に無い
POS_ACCESS_CODE（合言葉）が設定されていません合言葉が空になっている
Access denied for user接続先のユーザー名かパスワードがちがう。TiDB Cloud でパスワードを作り直して入れ直す
getaddrinfo ENOTFOUND接続先のHOSTがちがう（コピーのし忘れ・余分な文字）
Health check 〜 timed outほとんどは接続先のまちがい。上の2つを確認
アドレスを開いても、なかなか表示されない

無料プランの休止から起き上がるところです。1分ほど待ってから読み込み直してください。営業中はこうなりません。

合言葉・名簿・店の名前を変えたい

Render の Environment で値を変えて Save Changes を押すと、1〜2分で反映されます。 合言葉を変えると、全員がもう一度合言葉を入れることになります。名簿から外した人は、すぐに使えなくなります。

管理者がPINを忘れた

Render の Environment で POS_ADMIN_RECOVERY_CODE を追加（16文字以上のでたらめな英数字）して保存し、 6章の3〜5の手順でPINを決め直します。終わったら必ず消します（6章の6）。

メンバーがPINを忘れた・申請コードが分からなくなった

PINを忘れた人は、管理者が PIN タブでリセットします。申請コードが分からなくなった人は、もう一度PINを設定すると新しいコードが出ます。

練習の記録を消したい／最初からやり直したい

練習用の商品で練習したなら、商品タブの 練習を片付ける で練習の分だけ消えます。 すべて消したいときは、商品タブの リセット（全データリセット）を使います。商品・売上・在庫・現金の記録・操作ログがすべて消えます（PINと報告書の設定は残ります）。

当日、レジが動かなくなった

「障害対応手順書」（docs フォルダのPDF）に、画面ごとの対応と、紙での営業の方法が書いてあります。前もって印刷しておいてください。

キャッシュレス決済（PayPayなど）を使いたい

決済会社との契約が必要です。準備の方法は docs/cashless-payment.md にあります（くわしい人向け）。設定しなければ現金だけで動きます。
